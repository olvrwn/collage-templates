# Template format specification (schema v1)

This file is the single source of truth for what `template.json` and `manifest.json` mean.
`tools/build.py` validates against it and contains the reference layout implementation (`layout_slot`).
The iOS app must reproduce the geometry exactly.

## Files
```
manifest.json                       generated by tools/build.py – never edit by hand
templates/<id>/template.json        single source of truth for one template
templates/<id>/thumb.jpg            preview image (600 px wide recommended)
templates/<id>/assets/*             optional images referenced by decorations
```
All paths in the manifest are relative to the manifest URL.

## manifest.json
Top level: `schemaVersion` (int), `updatedAt` (ISO 8601 UTC), `templates` (array).
Per entry: `id`, `version` (int, bump on every change of template.json), `name` (object language → string,
`en` always present, fall back to `en`), `category`, `tags`, `aspectRatio` ("W:H"), `photoCount`,
`thumbnail`, `definition`, `sha256` (of template.json), `assets` (`[{path, sha256}]`).

Categories currently in use: `grid`, `polaroid`, `film`, `editorial`, `photobooth`, `scrapbook`.
The app must derive its filter chips from the categories present in the manifest (unknown categories are
shown with the raw id, capitalised).

## template.json
```
schemaVersion, id, version, name{}, category, tags[],
canvas{aspectWidth, aspectHeight, backgroundColor},
defaults{borderColor, borderWidth, gap, cornerRadius, outerPadding},
customizable{...}, slots[], decorations[]
```

### Coordinate system
- Slot and decoration `x`, `width` are fractions of the **content-area width**; `y`, `height` fractions of the
  **content-area height**. The content area is the canvas inset by `outerPadding × canvasWidth` on all sides.
- `borderWidth`, `gap`, `cornerRadius`, `outerPadding` and shadow `radius` are fractions of the **canvas width**.
  Shadow `offsetY` is a fraction of the canvas height.
- Colours are `#RRGGBB` or `#RRGGBBAA`.

### Slots (photo placeholders)
| field | meaning |
|---|---|
| `id` | unique within the template |
| `x, y, width, height` | **outer** rectangle including the frame. Changing `borderWidth` never moves it; the photo area shrinks instead |
| `rotation` | degrees, **clockwise-positive**, about the centre of the outer rectangle (frame, photo and shadow rotate together) |
| `zIndex` | slots and decorations share one z-order, ascending = on top |
| `frameStyle` | `none`, `solid`, `polaroid`, `film`. Unknown values behave like `solid` |
| `polaroidBottomRatio` | polaroid only, default 4 |
| `gapAware` | if true, the slot is inset by `gap × canvasWidth / 2` on every edge that is **not** on the content-area boundary (position < 0.001 or > 0.999). Gaps therefore appear only between neighbours. If false/absent, `gap` is ignored |
| `shadow` | optional `{radius, opacity, offsetY}` soft drop shadow |

Frame insets (px = value × canvasWidth):
- `none`: 0
- `solid`: `borderWidth` on all four sides
- `polaroid`: left/top/right = `borderWidth`, bottom = `borderWidth × polaroidBottomRatio`
- `film`: left/right = `borderWidth`, top/bottom = `borderWidth × 0.25`; rounded-square sprocket holes
  (size ≈ 0.38 × borderWidth, pitch ≈ 0.8 × borderWidth, vertically centred as a group) along the left and
  right borders, filled with the canvas background colour so they look punched out.

Corner radius: outer radius = `cornerRadius × canvasWidth`; photo radius = max(0, outer radius − smallest inset).

### Decorations
- `type: "shape"`: `shape` = `rect` (default) or `ellipse`; `color` is a hex colour **or** a token:
  `$borderColor` / `$backgroundColor` (resolved to the current user-chosen frame/background colour, so e.g. a
  photobooth strip changes colour with the frame-colour control); `opacity`; `x, y, width, height`; `rotation`; `zIndex`.
- `type: "image"`: `asset` (relative path), `x, y, width`, `rotation`, `opacity`, `zIndex`; height follows the
  image's aspect ratio.
- Unknown decoration types are ignored.

### defaults / customizable
`defaults` holds the initial values. `customizable` controls which UI controls exist:
colours (`borderColor`, `backgroundColor`) → `true`; numbers (`borderWidth`, `gap`, `cornerRadius`,
`outerPadding`) → `{min, max}`; absent or `false` → control hidden. `defaults.x` must lie inside its range.

### Compatibility
Unknown JSON keys are ignored. A template whose `schemaVersion` is higher than the app supports is skipped.

## Design rules of thumb (for new templates)
- Think in physical units first: unit width = `aspectWidth`, unit height = `aspectHeight`.
  A slot's real aspect ratio = (`width × aspectWidth`) / (`height × aspectHeight`). Keep photo cells between
  about 0.6 and 1.8 (w/h) so ordinary photos crop gracefully.
- Polaroid: with `borderWidth` b, bottom ratio r, slot width w (normalised) a *square* photo needs
  `height × aspectHeight = (w − 2b) × aspectWidth + b × aspectWidth × (1 + r)`
  (photo width in units, plus top border, plus bottom border). Example: 9:16 canvas, w = 0.44, b = 0.02, r = 4
  → height = (3.6 + 0.9) / 16 = 0.281.
- Keep rotated slots at least ~0.03 away from the canvas edge so corners stay visible.
- Grid templates: cells flush to the content-area edges, `gapAware: true`, white or neutral background.
- Free-form templates: `gapAware: false`, give every slot a distinct `zIndex`, add `shadow` for depth.
- Max 30 slots per template.
